# 程式碼審查

確認審查範圍，讀取相關需求、呼叫端、設定與測試，區分本次引入、既有但相關及範圍外問題。優先回報有實際影響的缺陷，不把純風格偏好列為 finding。

## 唯讀與證據

- 不修改程式碼、設定、工作樹或 Git index，不安裝套件、暫存、提交或推送。只執行不改變專案狀態的診斷。
- 每項問題須有程式證據或可重現路徑；證據不足時標示假設與不確定性。
- 只有目標包含 Dart／Flutter 時讀取 [專屬清單](references/codereview-flutter.md)。它是條件式檢查訊號；以專案設定、需求與既有慣例為準，不強迫架構、lint 套件或相依升級。

## 輸出

依嚴重程度排序，每項 finding 包含：

- **嚴重程度與問題**：高（安全、資料遺失、核心功能錯誤）；中（合理情境下的錯誤或顯著風險）；低（有具體影響的局部問題）。
- **位置**：檔案及可定位行號。
- **觸發條件、影響與證據**。
- **具體修正建議**；必要時提供精簡範例。

多項問題且有助閱讀時才加摘要表，不強制總評、diff 範例或核准徽章。沒有 finding 時寫「未發現需回報問題」，並說明未驗證範圍與殘餘風險；不表示保證無缺陷。

審查結束即回報，不自動啟動重構、文件更新或 Git 交付。
