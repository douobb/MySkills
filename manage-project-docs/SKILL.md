# 管理專案文件

預設只處理 `docs/`，優先沿用既有文件架構與導覽。保留有長期價值的獨特資訊，尤其是設計理由、取捨及限制；不以檔名、日期或篇幅決定去留，不改產品需求或程式行為。

## 盤點與方案

讀取全部一般與隱藏文件，按需要查閱設定、Git tracked／ignored 狀態及引用。二進位文件以合適工具讀取；無法讀取時標示待確認，不判定無用。不跟隨專案外符號連結。

| 分類 | 判定 |
|---|---|
| 公開且可保留 | 有明確讀者價值、正確可驗證、可獨立理解且沒有私有資訊 |
| 私有且可保留 | 有用但依賴內部規劃、任務追蹤、商業脈絡或未公開決策 |
| 需要整理 | 有可用內容，但混合雜訊、重複、過時內容或缺乏背景；需公開改寫或私有整合 |
| 建議移除 | 確實無獨特持續價值的暫存 log、重複輸出或失效草稿 |

公開文件須能脫離未上傳的 TODO、PRD、HANDOFF 獨立閱讀，有公開入口及必要術語定義；不能把未實作規劃寫成現況。`TASK-003`、FR、Phase 等內部代號須轉為有閱讀意義的領域說明，只有已公開定義且對讀者有用的代號才保留。移除私有脈絡後失去主要價值者維持私有；不確定時不推定可公開。

公開文件面向一般使用者與新開發者，不提及或連結私有、被忽略或未發布文件，也不揭露開發者私人事項與未公開後續規劃。必要安裝設定可用預留值說明建立方式，文件主題本身需要解釋 Git 忽略規則時可列必要路徑；不能藉此列出無關私有內容。私有盤點／交接等操作回報仍可記錄必要路徑，避免將它們混入公開產物。

整理或新增文件前判斷讀者用途與維護價值，不把每次功能變更都變成新文件或條目；既有過時說明仍須在核准範圍修正。長篇架構、安裝或參數說明可獨立成文件並由 README 連結，保留必要背景、摘要與入口，避免零碎、重複或只換檔名的拆分。只有使用者明確要求公開規劃且通過內容檢查時，才將相關內容納入公開文件。

逐檔條列路徑、簡介、分類、關鍵理由／風險、Git 狀態與建議動作；敏感內容只提供高階摘要。另列精確刪除清單、整合來源／目標／保留內容／來源處置、搬移位置、必要忽略與連結修正。

## 授權與執行

搬移、合併、刪除、改變 Git 忽略或公開範圍前，取得使用者對具體方案的確認；已有精確有效授權時不重複詢問，部分確認只執行已核准項目。純排版或明確指定的非破壞性小修改可直接執行。

已核准具體整理操作後，內容取捨、術語或編排等決策優先使用 `request_user_input`，取得回答後依既有授權繼續，不重新詢問操作許可。尚未核准的刪除、合併、搬移、忽略或公開變更仍屬操作授權，須展示精確方案並依當前允許的方式取得同意，不能包裝成內容選擇。

不僅因工具禁止權限請求就退回內容提問；工具不可用或明確禁止該類提問時才改用對話等待。取消、空回答或逾時不視為有效決定，未確認項目保持原樣；系統權限批准另依環境規則。

執行前核對方案仍符合現況，出現新衝突時更新方案。先完成目標文件並驗證獨特資訊與引用未遺失，再處置核准來源，最後修正受影響連結／導覽。未追蹤檔案刪除前說明復原限制，可行時採可復原方式。

只有實際文件需要時才建立 `guides/`、`reference/`、`architecture/` 等分類；小型專案可直接放 `docs/`，不建立空目錄、空文件或空索引。

## 私有文件保護

- `docs/PRD.md` 與 `docs/private/HANDOFF.md` 是受保護來源；未明確納入範圍，不改寫、整合、搬移或刪除。HANDOFF 不直接公開；PRD 公開需特定授權與敏感內容檢查。
- 核准私有歸檔時重用 `docs/private/` 與獨立忽略規則 `docs/private/`，缺少才增量補建，保留既有規則且不放 `.gitkeep`。維持 `docs/PRD.md`、根目錄 `TODO.md` 的預設私有邊界。
- 私有文件已 tracked／staged／待推送時回報精確路徑並停止相關 Git／公開操作；不自行取消追蹤。`.gitignore` 不清除追蹤或遠端歷史，不自動重寫歷史或強制推送。
- 發現真實憑證時停止處理相關內容，不輸出值，建議撤銷／輪替；將它搬進 `docs/private/` 不能補救暴露。

## 完成標準

分類與處置都在授權範圍，獨特決策保留，公開文件有獨立價值且無私有洩漏，私有規則正確，連結與導覽未失效。回報實際保留、建立、整合、移動、刪除及忽略變更與剩餘風險。不自動調用文件撰寫 Skill、修改 Git index、提交或推送；公開入口只做核准範圍內必要修正，涉及 README 時兩語同步。
