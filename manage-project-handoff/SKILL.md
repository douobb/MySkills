# 管理專案交接

以單一最新快照補足程式碼、PRD、TODO 無法直接傳達的短期背景。更新時保留仍有效限制與理由、替換過時狀態，不附加每輪 session log，不複製完整文件、diff 或對話。

## 建立或更新

讀取目前指示、既有快照與本輪相關文件、Git 狀態及驗證結果。只記錄接手需要且有依據的內容；有效的使用者特殊要求保留原意與適用範圍，期限或衝突只有影響下一步時才補充，不將臨時要求升級為永久規範。

```markdown
# Session Handoff

## 目前目標
## 已完成工作
## 重要決策與限制
## 未完成事項與阻塞
## 下一步
```

只保留有內容的章節。Git branch／HEAD、未提交檔案、驗證結果、關鍵路徑及更新時間在有助接手時附於相關章節；如實區分已執行、未驗證與過時結果。下一步保持精簡、可開始。

長期規範、需求、任務與公開行為仍以 `AGENTS.md`、PRD、TODO、README 為正式來源，快照只引用相關位置。發現正式文件需要更新時記為待辦；只有使用者要求或本次任務確實需要才另外處理，不自動連動。

## 恢復

先讀目前有效指示，再讀快照及其必要引用；核對目前檔案、branch／HEAD、工作樹與 Git 操作狀態。差異以目前證據為準，標示過時或待確認；不沿用無依據的「測試通過」，也不 reset、checkout 或清理工作樹來符合快照。

快照缺失時只重建可查證狀態並說明臨時脈絡缺口，不自造交接歷史。僅讀取／恢復不修改檔案或私有邊界；只有使用者要求繼續工作才執行下一步。

特殊要求是否延續、限制衝突或跨裝置安全傳遞方式需要使用者決定時，優先使用 `request_user_input` 提供具體選項與自由輸入；不可用或不允許該用途時改用對話等待，不把未回答的要求視為延續或新增授權。

## 私有邊界與授權

- 預設 `docs/private/HANDOFF.md`，不得直接公開；不保存 token、密碼、私鑰或完整敏感值。`docs/private/` 不是機密保管庫。
- 建立／更新前核對 tracked、staged 與可用的 outgoing 範圍；意外納入時停止並回報。恢復時發現暴露風險也要警示，不自行修改 index 或歷史。
- 寫入時重用既有 `docs/private/` 與獨立忽略規則 `docs/private/`；缺少才增量補建，不覆寫規則、不放 `.gitkeep`。有 Git 時驗證快照被忽略。`.gitignore` 不會取消既有追蹤或清除歷史。
- 被忽略的快照不會自動跨裝置同步；跨裝置傳遞須使用使用者指定的安全方式。
- 建立交接不授權實作、永久規範修改、提交或推送；刪除或清空快照需有明確要求，因未追蹤資料通常不能由 Git 復原。

完成時回報快照位置或恢復目標、有效限制、重要未決事項、可信下一步與驗證／傳遞限制。
