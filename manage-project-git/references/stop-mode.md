# Git 異常處理

停止暫存、commit、push 與其他擴大影響的動作，保留工作樹、index、branch、remote 與歷史。只收集足以決策的證據，不輸出機密值。

| 情況 | 回報與方案 |
|---|---|
| 憑證／私有內容 | 回報路徑、位置與風險類型。未提交時建議去敏、機密管理或忽略；已進 commit／遠端時優先撤銷或輪替，再評估歷史清理；忽略不能清除歷史 |
| 範圍外 staged 或混合 hunks | 指出精確範圍，提供保留、隔離本次修改或另行提交的選項，不自行取消暫存 |
| 本機落後／雙方分歧 | 說明兩側 commits 與協作者影響，提供 merge、rebase、新分支／PR 或暫不處理的取捨 |
| remote／upstream 不符或不相關歷史 | 列出目前與預期目標，提供更正、新分支／儲存庫或經確認整合方案 |
| 衝突或進行中的 Git 操作 | 列出操作狀態與檔案，請使用者決定內容或接續方式，不自行中止／清理 |
| 驗證、hook、認證、權限、網路或 push 失敗 | 回報失敗階段、精簡錯誤及安全修復選項，不跳過 hooks 或重要檢查 |

回報已完成動作、branch／HEAD／remote、必要 ahead／behind 與剩餘變更，再給推薦方案，優先用 `request_user_input` 提供具體選項與「暫不處理」，等待有效回答；工具不可用或當前規則不允許該用途時改用對話等待，不以取消、空回答或逾時推定同意。既有精確授權適用時只執行該項。未有明確授權不 unstage、pull、merge、rebase、更改 remote 或重寫歷史。

只有使用者明確要求改寫精確遠端分支並理解影響後才可考慮 `--force-with-lease`，不使用裸 `--force`。處理後重新核對狀態並重跑受影響檢查。
