# 撰寫專案 TODO

預設輸出根目錄 `TODO.md`。依目前明確指示、PRD 有效需求與程式碼／測試證據規劃；PRD 缺失時仍可建立有限清單，但列出資訊缺口，不虛構需求。

## 粒度與更新

先讀既有 TODO，保留有效任務、進度與 ID，只更新受影響工作。任務須可執行、成果明確、粒度適中且能判定完成；按需要納入測試、文件與整合工作。

優先順序或範圍取捨無法由有效需求、依賴與目前指示決定時，優先使用 `request_user_input` 提供選項與自由輸入；不可用或不允許該用途時改用對話，未回答則保留待確認，不擅自修改需求。

小型專案預設使用輕量清單：

```markdown
# 專案實作規劃

## 目前狀態
- 下一步：完成登入流程及相關測試。

## 待辦事項
- [ ] 實作登入與登出流程
- [ ] 驗證登入失敗與 session 過期
```

需要需求追蹤、跨階段依賴或多人協作時才增加欄位，例如：

```markdown
- [ ] TASK-002 登入與登出流程
  - 對應需求：FR-001
  - 依賴：TASK-001 使用者資料模型
  - 驗證：登入、登出與失敗情境測試
```

- 已有 TASK ID 維持穩定，不無故重排、重新編號或重用刪除 ID。
- 只有真實依賴才檢查排序與循環；循環需調整拆分或列為阻塞。
- 階段、阻塞、延後、待確認與進度百分比只在有用且有可靠資料時加入。
- `[x]` 須有符合任務範圍的實作與相關驗證證據；檔案存在不代表完成。部分完成或未驗證保持 `[ ]` 並記錄尚缺部分。
- TASK 完成不代表 FR 驗收；FR 須逐項符合其適用驗收條件，不能由單一 TASK 推斷。
- 不臆測工時、進度或測試結果，不保存憑證或不必要個資，不建立空章節。

## 私有邊界

寫入前檢查 `.gitignore` 及 TODO 的 tracked／staged 狀態；有可用 upstream 或指定推送目標時也核對本機 outgoing commits，無法判定則回報限制。無明確公開授權而已 tracked、staged 或待推送時停止並回報，不自行取消追蹤或改寫歷史。

預設保留獨立規則 `TODO.md`，缺少時增量補上並核對忽略狀態，不覆寫其他規則。`.gitignore` 不會解除追蹤或清除歷史。公開特定 TODO 須明確指示且先檢查內部追蹤、商業規劃、個資及安全資訊；必要時建議去敏的公開 roadmap。一般「全部上傳」不構成公開授權。

## 完成標準

任務可執行、完成狀態有證據、必要依賴合理、下一步清楚且保持私有。回報主要任務變更、阻塞與未驗證事項；不修改 PRD、不開始實作，也不自動更新其他文件或暫存、提交、推送。
